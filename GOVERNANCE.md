## 📋 Processo de Tomada de Decisão / Decision-Making Process

### 🔹 Decisões Rotineiras / Routine Decisions

**Exemplos / Examples**: Bug fixes, pequenas melhorias, documentação

**Processo / Process**:
1. Pull Request é criado / Pull Request is created
2. Revisão do mantenedor / Maintainer review
3. Aprovação e merge / Approval and merge
4. **Tempo máximo / Maximum time**: 7 dias úteis / business days

### 🔹 Decisões Importantes / Important Decisions

**Exemplos / Examples**: Novas features, mudanças de arquitetura, adição de dependências

**Processo / Process**:
1. Proposta via Issue ou Discussion / Proposal via Issue or Discussion
2. Período de discussão (mínimo 7 dias) / Discussion period (minimum 7 days)
3. Feedback da comunidade / Community feedback
4. Decisão do mantenedor com justificativa / Maintainer decision with rationale
5. Documentação da decisão / Decision documentation

### 🔹 Decisões Críticas / Critical Decisions

**Exemplos / Examples**: Mudança de licença, alteração de governança, remoção de features principais

**Processo / Process**:
1. Proposta formal via Issue / Formal proposal via Issue
2. Período de discussão (mínimo 30 dias) / Discussion period (minimum 30 days)
3. Consulta a contribuidores ativos / Consultation with active contributors
4. Votação se necessário / Voting if necessary
5. Decisão requer consenso ou maioria qualificada (75%) / Decision requires consensus or qualified majority (75%)
6. Documentação detalhada da decisão / Detailed decision documentation

## 🗳️ Processo de Votação / Voting Process

### Quando Votar / When to Vote

Votações são convocadas para decisões críticas quando:
- Não há consenso após período de discussão
- Múltiplas propostas válidas existem
- Mudanças significativas são propostas

Votes are called for critical decisions when:
- There is no consensus after discussion period
- Multiple valid proposals exist
- Significant changes are proposed

### Quem Pode Votar / Who Can Vote

- **Mantenedor Principal**: 1 voto com veto em questões de segurança / 1 vote with veto on security matters
- **Contribuidores Ativos**: 1 voto cada / 1 vote each
- **Contribuidores**: Voto consultivo / Advisory vote

### Quórum

- **Mínimo**: 3 votos (incluindo mantenedor) / Minimum: 3 votes (including maintainer)
- **Decisões Críticas**: 75% de aprovação / Critical decisions: 75% approval
- **Decisões Importantes**: Maioria simples (50% + 1) / Important decisions: Simple majority (50% + 1)

## 🔄 Processo de Pull Request / Pull Request Process

### 📝 Requisitos / Requirements

Antes de submeter / Before submitting:
- [ ] Código compila sem erros / Code compiles without errors
- [ ] Testes passam (se aplicável) / Tests pass (if applicable)
- [ ] Documentação atualizada / Documentation updated
- [ ] Segue Code of Conduct / Follows Code of Conduct
- [ ] Commits seguem convenções / Commits follow conventions

### 🔍 Processo de Revisão / Review Process

1. **Submissão / Submission**: Contributor cria PR
2. **Revisão Automática / Automated Review**: CI checks (quando disponível)
3. **Revisão de Código / Code Review**: Mantenedor revisa código
4. **Feedback / Feedback**: Comentários e sugestões
5. **Iteração / Iteration**: Contribuidor ajusta se necessário
6. **Aprovação / Approval**: Mantenedor aprova
7. **Merge**: Integração ao projeto

**Tempo de Resposta Esperado / Expected Response Time**:
- Primeira resposta: 3-7 dias úteis / business days
- Revisão completa: 7-14 dias úteis / business days

### ✅ Critérios de Aprovação / Approval Criteria

- ✅ Código limpo e bem documentado / Clean and well-documented code
- ✅ Não quebra funcionalidade existente / Doesn't break existing functionality
- ✅ Segue padrões do projeto / Follows project standards
- ✅ Beneficia o projeto / Benefits the project
- ✅ Não introduz vulnerabilidades de segurança / Doesn't introduce security vulnerabilities

## 🔐 Responsabilidade e Proteção / Responsibility and Protection

### 🛡️ Proteção aos Contribuidores / Contributor Protection

**Garantias Legais / Legal Guarantees**:

1. **Não Responsabilização / Non-Liability**:
   - Contribuidores não são responsáveis por bugs ou problemas
   - Licença MIT protege de ações legais
   - Responsabilidade é do mantenedor principal

2. **Propriedade Intelectual / Intellectual Property**:
   - Contribuidores mantêm copyright de suas contribuições
   - Histórico Git preserva autoria
   - Não pode ser removido ou alterado

3. **Reconhecimento / Recognition**:
   - Listagem em CONTRIBUTORS.md
   - Preservação no histórico Git
   - Crédito em release notes

### ⚖️ Responsabilidade do Mantenedor / Maintainer Responsibility

**O mantenedor principal é responsável por / The main maintainer is responsible for**:

1. **Decisões do Projeto / Project Decisions**:
   - Direção técnica
   - Aceitação de contribuições
   - Releases e versões

2. **Aspectos Legais / Legal Aspects**:
   - Conformidade com licença
   - Proteção de contribuidores
   - Questões de propriedade intelectual

3. **Segurança / Security**:
   - Resposta a vulnerabilidades
   - Proteção de usuários
   - Comunicação de riscos

4. **Comunidade / Community**:
   - Aplicação do Code of Conduct
   - Resolução de conflitos
   - Manutenção de ambiente saudável

## 🔄 Sucessão e Continuidade / Succession and Continuity

### Transferência de Manutenção / Maintenance Transfer

**Cenários / Scenarios**:

1. **Mantenedor se Afasta / Maintainer Steps Down**:
   - Nomeação de novo mantenedor com 30 dias de antecedência
   - Consulta a contribuidores ativos
   - Documentação de transição

2. **Mantenedor Inativo / Inactive Maintainer**:
   - Após 6 meses sem resposta
   - Contribuidores ativos podem solicitar transição
   - Processo de votação para novo mantenedor

3. **Fork do Projeto / Project Fork**:
   - Qualquer um pode fazer fork sob licença MIT
   - Fork deve manter atribuições originais
   - Novo nome recomendado para evitar confusão

### Preservação de Direitos / Rights Preservation

**Garantias / Guarantees**:
- ✅ Histórico Git nunca será reescrito / Git history will never be rewritten
- ✅ Contribuições mantêm atribuição / Contributions maintain attribution
- ✅ Licença não pode ser retroativamente mudada / License cannot be retroactively changed
- ✅ CONTRIBUTORS.md será preservado / CONTRIBUTORS.md will be preserved
